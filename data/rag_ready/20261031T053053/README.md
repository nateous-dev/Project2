# 상담 RAG 입력 자료

2026-10-31 공개 원문을 새로 수집한 결과입니다. 6개 후보 중 5개 수집 성공, BAI는 기존 자동 수집 금지 확인에 따라 제외했습니다. 이번 실행의 원시 분할은 319개이며 이전 실행 결과와 다를 수 있습니다.

## 사용할 파일

- knowledge.jsonl: 정제·주제 태깅한 검색 입력 자료
- quality_report.json: 문서별 수량, 주제 분포, 한계
- retrieval_rules.json: 출처 표시·검색 구분·답변 제한 규칙
- review_excluded.jsonl: 짧은 본문, 목차, 중복, 상담 주제 미검출 등을 분리한 검토 목록
- source_run/: 새 수집 원문, 추출 텍스트, 출처 목록과 로그
- evaluation_cases.jsonl: 초기 검색 품질 점검 질문. 정답률을 측정한 결과가 아닙니다.

## 정리한 내용

PDF 페이지 단위를 유지하고 줄바꿈·불필요한 제어문자·일부 반복 머리말을 정리했습니다. 문단 경계를 우선해 최대 1,400자, 약 200자 중첩으로 나눴습니다. 국가, 발행연도, URL, PDF 페이지, 원문 해시, 문서 성격과 주제 태그를 붙였습니다. HTML의 page는 null입니다. 정제 전후 분할 경계가 달라져 원시 조각 수와 단순 차감 관계가 아닙니다.

## 검색 설계

guide는 상담 절차·권리 안내, retention은 고객 관계·서비스 개선 전략입니다. 하나은행 규정은 해당 은행의 규정이며 다른 은행의 공통 규정이 아닙니다. 해외 전략은 일반 참고자료로 분리하세요.

모델 신호 → 확인할 질문 → 고객이 말한 불편 → 관련 문서 검색 → 출처가 있는 초안 → 상담원 검토 순서를 권장합니다. 비활성이라는 모델 입력만으로 앱 오류·수수료 불만을 확정하지 않습니다. 제공되지 않은 특별금리나 수수료 면제를 약속하지 않습니다.

주제 태깅은 규칙 기반 초안이며 은행 전문가의 전수 검수가 아닙니다. 표·다단 PDF의 읽기 순서, 일부 본문에 남은 사례·인용·숫자는 추가 검토가 필요합니다. 신용·대출·상품 추천을 자동 확정하는 용도로 승인된 자료가 아닙니다. 원문과 비교 가능한 상태로 보관했습니다.

현재는 벡터DB·임베딩·LLM 연결 전입니다. 임베딩 시 사용할 본문 필드는 text이며 나머지는 필터·출처 메타데이터로 보존하세요. 공개 원문의 이용조건은 실제 서비스 공개 전에 확인해야 합니다.

## 재현

프로젝트의 prepare_rag.py에 --input 수집실행폴더 --output 정제폴더를 전달하면 같은 규칙으로 다시 정리할 수 있습니다. 이번 실행은 기존 agent 환경의 requests/bs4/cryptography와 작업 폴더에 복사한 번들 pypdf를 사용했습니다. 전역 Python 환경은 변경하지 않았습니다. 향후 일반 실행에는 requirements-rag.txt의 패키지를 설치하세요.
